# 외국인 근로자 작업지시 이해확인 동료

2026 AI 우왕톤 (주제: "AI는 동료가 될 수 있을까?", 현장: 산업 현장) 출품작. 1인 개발.

반장이 한국어로 작업지시를 입력하면 AI가 근로자 모국어로 쉽게 풀어 주고, **확인 질문으로 진짜 이해했는지 검사해서 못 알아들은 사람을 반장에게 알려 주는** 웹앱입니다. AI는 번역기가 아니라 "이해했는지 확인하는 동료"이고, 재설명·투입 결정은 반장(사람)이 합니다.

## 문제

제조 현장 외국인 근로자는 한국어 작업지시·안전교육을 충분히 이해하지 못한 채 투입되는 경우가 많고, 반장은 "알아들었냐"에 "네"라는 답만 들어서 누가 이해하지 못했는지 알 수 없습니다.

- 2025년 상반기 재해조사 대상 사고사망 287명 중 외국인이 38명(13.2%) (뉴시스, 2025-08-21)
- 외국인 산재 승인 9,872명, 전년 대비 7.1% 증가, 건설·제조업 집중 (한국경제, 2026-07)
- 언어 장벽으로 외국인 고용 사업장의 안전교육이 어려움 (안전보건공단 충북북부지사, 마이데일리 2024-11-06); 부실한 외국어 교육 후 현장 투입 지적 (서울신문, 2024-06-26)
- 한국어 중심 교육·자막 의존 시 이해도가 떨어지고 통역 비용이 부담 (강남구 보도자료)
- 한계: 외국인 근로자 교육의 **이해도를 수치로 측정한 조사는 찾지 못했습니다.** 이 서비스가 바로 그 측정을 합니다.

### 기존 서비스와 차별점

강남구 QR 다국어 안전교육, 건설사 AI 번역앱 등은 대부분 건설현장 중심의 **일방향 전달**입니다. 이 서비스는 **제조업**을 대상으로 **이해 확인 + 반장에게 피드백**하는 양방향 구조입니다.

## 사용자 흐름

1. 반장이 교육 세션을 만들고 한국어로 작업지시를 입력(텍스트 또는 음성)합니다. QR/링크가 생성됩니다.
2. 근로자가 폰으로 QR에 접속해 이름과 언어를 고릅니다. 로그인은 없습니다.
3. AI가 근로자 모국어의 쉬운 말 단계별 설명(단계마다 이모지)과 객관식 확인 질문 2~3개를 만듭니다.
4. 근로자가 답하면 하나라도 틀릴 때 반장 화면에 🔴, 모두 맞으면 🟢가 표시됩니다.
5. 반장이 재설명(더 쉬운 설명을 다시 생성해 3번으로) 또는 투입을 결정합니다. **최종 결정은 사람입니다.**

## 직접 구현 vs 외부 기술

| 구분 | 내용 |
|---|---|
| 직접 구현 | 세션·근로자 상태 흐름, 객관식 채점(🔴/🟢 판정), 재설명 단계(level) 관리, 지시문 단위 결과 캐시, 시간당 호출 상한, 반장/근로자 화면, 검증 스크립트(`scripts/validate.ts`), 개발 하네스 가드(아래) |
| 외부 기술 | Claude API (기본 `claude-haiku-5-5`, `LLM_MODEL`로 교체), Turso/libSQL (DB), Vercel (배포), `qrcode` (QR 생성), 브라우저 Web Speech API (음성 입력), Next.js |

LLM 호출은 `lib/llm.ts` 한 파일에만 있어 다른 제공사로 바꿀 때 그 파일만 고치면 됩니다.

## AI의 역할과 검증

**AI가 하는 일**: 한국어 지시 → 근로자 모국어 변환, 전문용어를 쉬운 말로 풀기, 단계별 이모지 설명, 확인 질문과 보기(오답 포함) 생성. 채점은 객관식 정답 비교라 AI가 하지 않습니다.

**검증 방법** (`scripts/validate.ts`): 고용노동부 공개 자료(moel.go.kr)를 바탕으로 만든 지시문 30건(`data/validation/instructions.json`, 건별 출처 기재)을 베트남어·네팔어·영어로 생성해 다음을 측정합니다.

- 역번역 일치도: 생성 결과를 다시 한국어로 번역해 원문과의 의미 일치를 1~5점으로 판정
- 질문 품질: 확인 질문이 원문의 핵심 안전 사항을 담는지, 정답이 하나뿐인지

```bash
npx tsx scripts/validate.ts --langs vi,ne,en   # 실제 API 호출, 승인 필요
```

결과 보고서는 `results/`에 저장됩니다. 실제 API 1회 실행 결과: (제출 전 기입). mock 상태에서 실행하면 파일명에 `MOCK`이 붙고 "샘플 데이터(모킹)" 경고가 들어가며 실제 결과가 아닙니다.

## 한계

- 원어민 검수를 하지 못했습니다. 번역 품질은 모델 판정 중심이며, 사람의 직접 확인은 일부 건에 한정됩니다.
- 생성과 판정(역번역·질문 품질)을 같은 모델이 하므로 같은 오류를 둘 다 놓칠 수 있습니다.
- mock 모드에서는 재설명 단계에도 같은 샘플 내용이 나와서 "더 쉬운 설명"이 실제로 달라지지 않습니다.
- 검증 데이터셋은 고용노동부 공개 자료를 요약한 문장이며, 일부는 사고 사례에서 추론한 것입니다. 공식 표준작업 문구가 아닙니다.
- 현장 인터뷰·실사용 시험은 하지 못했습니다(현장 가정은 충북 중소 제조공장이며 추측).

## 실행 방법

Node.js 24 기준 (CI와 동일).

```bash
npm ci
npm run dev        # mock 모드, API 키 불필요 (http://localhost:3000)
npm run dev:live   # 실제 Claude API 사용, .env.local 필요
npm test           # 테스트는 항상 mock
```

`.env.local`을 만들어 아래 값을 채웁니다 (`.env.example` 참고). 키는 커밋하지 않습니다.

| 변수 | 설명 | 기본값 |
|---|---|---|
| `ANTHROPIC_API_KEY` | Claude API 키. 없으면 자동으로 mock | (없음) |
| `DATABASE_URL` | Turso/libSQL URL. 비우면 로컬 `file:local.db` | `file:local.db` |
| `TURSO_AUTH_TOKEN` | Turso 인증 토큰 (로컬 파일 DB에는 불필요) | (없음) |
| `LLM_MOCK` | `1`이면 항상 고정 샘플 응답 사용 | `0` (`npm run dev`는 `1`) |
| `LLM_HOURLY_CAP` | 시간당 실제 LLM 호출 상한 (캐시 적중은 제외) | `100` |
| `LLM_MODEL` | 사용할 Claude 모델 | `claude-haiku-5-5` |

## mock 표시 정책

대회 규정상 고정 결과를 실제 AI처럼 보여 줄 수 없습니다. mock 응답이 쓰이면 화면에 **"샘플 데이터(모킹)"** 배지가 표시되고, 검증 보고서에도 같은 경고와 `MOCK` 파일명이 붙습니다. 배포 환경은 `LLM_MOCK=0`과 API 키로 실제 호출을 하며 배지가 보이지 않아야 합니다.

## 개발 하네스

AI 코딩 도구로 개발했기 때문에 실수로 API를 쓰거나 경계가 깨지지 않도록 가드를 두었습니다.

- LLM 경계 테스트(`tests/boundary.test.ts`): `@anthropic-ai/sdk`를 import하는 파일이 정확히 `lib/llm.ts` 하나인지 양방향으로 검사 (위반 탐지기 자체도 테스트)
- 테스트 환경에서 API 키를 제거하고 기본 mock으로 고정 (`tests/setup.ts`)
- 실제 API를 쓰는 명령(`validate.ts`, `npm run dev:live`)은 `.claude/settings.json`에서 실행 전 승인 필요, `.env` 읽기는 차단
- CI(`.github/workflows/ci.yml`) 단일 job: `npm ci` → `lint` → `next build` → `tsc --noEmit` → `npm test` (`LLM_MOCK=1`)
